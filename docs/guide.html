punch 功能说明

一个二进制里的服务端和客户端。客户端主动连出去，服务端把收到的 TCP 交给客户端，由客户端去拨它能访问的地址。

它做什么

用法和 nps 同一类。内网机器运行客户端，公网机器运行服务端。访问服务端上的一个端口，流量会从已经建好的隧道进到客户端，再由客户端连到目标 IP 和端口。

  • 服务端可以监听 0.0.0.0（对外）或 127.0.0.1（只本机）。控制端口、数据端口、管理页、每一条映射都可以单独选。
  • 目标不限于客户端本机。客户端能解析、能连上的地址都可以，例如 10.0.0.8:80、192.168.1.9:22。
  • 映射保存在服务端。管理员在管理页里新增、修改和删除。被允许的客户端连上之后，也可以用 punch map 改自己的映射。
  • 客户端拨目标失败时，原因会回到服务端，管理页和 /api/events 都能看到。

跑起来

发布二进制是 target/release/punch。第一次执行服务端时，当前目录没有 punch-server.yaml 就会生成配置，并写一份自签名证书。终端会打出 api key，只在生成那一次出现。

punch server
punch client --server 127.0.0.1:8024 --secret <secret>

然后访问 http://<服务端>:18080，连接会到客户端能访问的 10.0.0.8:80。管理页是 https://<服务端>:8443/，证书域名是 localhost，浏览器需要信任这张自签名证书。

默认端口：控制 0.0.0.0:8024，数据 0.0.0.0:8025，管理页 0.0.0.0:8443。客户端连的是控制端口。数据端口由服务端在握手里告诉客户端，客户端用同一台机器的地址去连。

数据怎么走

访问方连服务端映射端口
→
服务端接受公网 TCP
→
客户端已有的数据连接
→
目标客户端能访问的 host:port

有两条 TCP，都是客户端向外拨号：

  • 控制连接用来登记映射、心跳、下发「开一条流」。大约 15 秒一次心跳，45 秒没有读到数据就断开并重连。
  • 数据连接只搬字节。服务端按配置预留一批空闲连接，新进来的访问优先用空闲的那条，省掉当场再拨号。

Linux 上接入用 epoll，两个 TCP 之间用 splice，字节留在内核里。其他 Unix（包括 macOS）用系统的事件接口，在用户态拷贝。启动服务端时会打印当前模式，/api/ping 的 io 字段也是这个值：Linux 上是 epoll+splice，macOS 上是 kqueue+copy。

每条接受或拨出的 TCP 都会打开 TCP_NODELAY，发送和接收缓冲默认 4MB，并打开 keepalive。进程会尽量把可打开文件数抬到 100 万（不超过系统硬限制）。

端口映射

映射全部由服务端保存，在配置旁边的 punch-clients.json 里。客户端连接时不能带 -m。管理员改完之后，在线客户端马上改用新的监听和目标；客户端不在线时映射留着，下次连上会收到全部最新配置。

客户端自己改

先运行 punch client。只有管理页允许「自己改映射」的客户端，才能在另一条命令里增删改。

punch map list
punch map add 0.0.0.0:8080=10.0.0.8:80
punch map update 3 0.0.0.0:8080=10.0.0.9:80
punch map del 3
  • 等号左边是服务端要监听的 ip:port，右边是客户端能访问的 host:port。
  • 当前目录有多个客户端时，用 punch map --addr 127.0.0.1:端口 指定。端口在客户端连上时打印。
  • 服务端没允许时，命令失败，原文是「服务端没有允许这个客户端自己改映射」。

服务端接口

客户端在线时，可以用管理页或下面的请求增加一条。客户端当时不在线也可以先开：监听先起来，等这个名字的客户端回来再开始转发。

curl -k -H "X-Api-Key: KEY" -H "Content-Type: application/json" \
  -d '{"client_name":"edge","bind":"0.0.0.0:18080","target":"10.0.0.8:80"}' \
  https://127.0.0.1:8443/api/mappings

成功是 HTTP 201。正文里有映射 id、实际绑定的 bind、target。目标当时拨不通时，映射仍然保留，warning 里是原因。监听地址绑不上（端口被占用、地址不合法）是 HTTP 400，事件类型是 bind_fail。

bind 必须是 ip:port，不能写域名。端口可以是 0，表示由系统分配，实际端口在响应和管理页里。同一 IP 上，非 0 端口不能和已有映射冲突。

配置文件

默认读 ./punch-server.yaml，用 punch server -c FILE 换路径。文件不存在就生成。相对路径的证书按 yaml 所在目录解析。只支持这种两层结构：顶层键、缩进一层的段落、# 注释、引号字符串。

control_listen: "0.0.0.0:8024"
data_listen: "0.0.0.0:8025"
api_key: "至少 8 个字符"

web:
  listen: "0.0.0.0:8443"
  cert: "certs/cert.pem"
  key: "certs/key.pem"

tcp:
  nodelay: true
  recv_buffer: 4194304
  send_buffer: 4194304
  pipe_size: 262144
  backlog: 4096

pool:
  idle: 16
  max_idle: 64
字段作用
control_listen客户端连入的控制端口。
data_listen数据连接端口。客户端使用握手里返回的实际端口。
api_key只给管理页。客户端用各自的 secret 登录，不使用这把 key。去掉首尾空白后至少 8 个字符。
web.listenHTTPS 管理页。
web.cert / web.keynginx 那两份 PEM：ssl_certificate 和 ssl_certificate_key。
tcp.pipe_sizeLinux splice 用的管道容量，限制在 64KB 到 4MB。越大单连接越不容易被管道堵住，内核内存也越高。
tcp.backlog监听队列，限制在 128 到 65535。
pool.idle每个客户端保持的空闲数据连接数，至少 1。
pool.max_idle空闲连接上限。客户端 --pool 不能超过它。

两份证书必须同时有，或同时没有。都没有时，启动会调用本机 openssl 生成一张 10 年的自签名证书，SAN 是 DNS:localhost 和 IP:127.0.0.1。只有其中一个文件时，启动直接失败，避免盖掉你已经放好的那一半。

客户端

参数作用
-s, --server HOST:PORT服务端控制地址。可以是 IP，也可以是能解析的域名。
--secret SECRET管理页给这个客户端分配的 secret。8 到 128 个字符。同一把 secret 只能有一台机器连着，后来的登录会让原来的退出并且不再重连。
--bench ADDR在客户端开一个明文 HTTP，用来压测隧道。
--expose-bench BIND把上面的 HTTP 映射到服务端的 BIND。需要同时写 --bench，并且这个客户端要被允许自己改映射。
--pool N预连接数量。省略则用服务端通告的 pool.idle，并且不会超过 max_idle。

控制连接断开后，客户端会从 1 秒开始重试，最长间隔 15 秒。日志用环境变量 RUST_LOG=debug 打到标准错误，可选 error、warn、info、debug。

管理页

页面编译进二进制，部署时不带额外文件。打开管理页后用顶部页签切换，不要在一个长页面里找功能。密钥只放在这个标签页的 sessionStorage 里，页面源码和接口响应都不会把当前密钥写出来。

  • 客户端：不用登录。三个系统的下载，以及怎么用 --secret <secret> 连接。页面源码里没有真实 secret。
  • 账号：登录后新建客户端、复制 secret、允许或禁止它自己改映射、更换 secret、删除。更换 secret 或删除会让当前连接退出。
  • 概览：在线客户端、映射、正在转发的连接、流量，以及控制通道、数据通道、管理页各自的地址。
  • 映射：选择客户端（可以离线），监听 0.0.0.0 或 127.0.0.1，填写目标 host:port。表格里可以直接改监听和目标。正常是绿色，客户端不在线是黄色，最近一次错误是红色。
  • 事件：上线、下线、绑定失败、目标没监听、目标不可达。同一句错误五秒内不重复。
  • 设置：登录后修改管理页的 api key。这把 key 不给客户端用。新密钥写回 yaml，立刻生效。其他管理页会退出。

/、/healthz、/favicon.ico 和 /dl/punch-macos、/dl/punch-linux、/dl/punch-windows.exe 不需要密钥。/healthz 返回 ok。

证书。管理页用系统 OpenSSL 读 PEM，和 nginx 同一套：证书链文件加私钥文件。私钥可以是 PRIVATE KEY、RSA PRIVATE KEY 或 EC PRIVATE KEY。换证书时改 yaml 里的路径，两份文件都放好，然后重启服务端。

HTTP 接口

/api/ 下面都要带密钥，请求头用 X-Api-Key，或 Authorization: Bearer <key>。密钥不对是 401。比较是按字节进行的。

方法路径返回
GET/api/pingpong 和当前 io 模式。用来确认接口和数据面。
GET/api/overview客户端数、映射数、正在转发的连接数、bytes_in / bytes_out、三个监听地址、运行毫秒数。
GET/api/clients已配置的客户端：name、secret、allow_maps、online、addr、connected_ms、pool_idle。只在管理接口返回 secret。
POST/api/clients正文 {"name","secret","allow_maps"}。secret 可省略，由服务端生成。名字或 secret 重复是 409。
PUT/api/clients/:name正文可带 secret 和 allow_maps。更换 secret 会通知在线客户端退出。只改权限时在线客户端马上收到新权限。
DELETE/api/clients/:name删除客户端和它的映射，并通知在线客户端退出。
GET/api/mappings每条映射的 bind、target、客户端是否在线、活跃连接、accept 次数、流量、fail_count、last_error。
POST/api/mappings正文 {"client_name","bind","target"}。201 时带 id、bind、target，可能有 warning。
PUT/api/mappings/:id正文 {"bind","target"}。只改目标时不重新监听。改监听时先绑新端口，成功后再停掉旧的。
DELETE/api/mappings/:id关掉监听，并通知在线客户端删掉这条。不存在是 404。
GET/api/events最近 200 条，新的在前。字段是 ts_ms、kind、client_name、map_id、message。
POST/api/key正文 {"api_key":"..."}。至少 8 个字符，不能含引号、反斜杠或控制字符。成功只返回 {"ok":true}，响应里没有密钥。写入配置文件并立即替换内存中的密钥。

事件 kind 有这些：client_online、client_offline、bind_fail、listen_fail、target_error。

失败上报

服务端把一条映射交给客户端时，客户端会先试拨目标，大约等 500 毫秒。连接被拒绝（对端没有 listen）时，消息以 listen failed: 开头，映射留在服务端，last_error 写成这句，事件类型是 listen_fail。其他拨号错误（域名失败、超时、网络不可达）记成 target unreachable:，事件类型是 target_error。

真正有访问进来、空闲连接或新数据连接上去拨目标时，同样的失败也会写回。同一条错误在 5 秒内不重复记事件，fail_count 每次都会加。内容变了会立刻再记一条。映射被修改或客户端探测成功时，last_error 会清掉。

用接口创建时，探测失败不会把映射删掉。201 的 warning 就是客户端回的那句话，客户端不在线或 2 秒内没确认时，warning 是 client offline 或 client ack timeout。

压测

客户端上的 --bench 是一个专门用来把隧道打满的明文 HTTP，不经过管理页的 TLS。

punch client --server 10.0.0.1:8024 --secret <secret> \
  --bench 127.0.0.1:19090 --expose-bench 0.0.0.0:18080

wrk -t4 -c256 -d30s http://10.0.0.1:18080/bench?size=1048576
  • GET /bench?size=N、GET /、GET /io：按块吐出 N 字节，默认 64KB，最大 32MB。内容是重复的 0xA5。响应头有 X-Punch-Bench: 1。
  • POST /bench 或 POST /io：把请求体读完，返回 {"bytes":N}，用来测反方向。
  • GET /health：返回 ok。

--bench 的地址如果是 0.0.0.0 或 ::，暴露到服务端时，客户端实际拨的是 127.0.0.1 或 ::1 上的那个端口。

要把吞吐打满，把系统的 net.core.rmem_max 和 net.core.wmem_max 调到不小于配置里的 4MB 缓冲。Linux 上还可以按连接加大 tcp.pipe_size。

部署

业务是一个文件：punch server 和 punch client 都在里面，管理页也在里面。HTTPS 在运行时链接系统的 OpenSSL，所以机器上要有 libssl（OpenSSL 3，装了 nginx 的系统通常已经有）。证书继续用 nginx 的那两份 PEM，不必换格式。

在 Linux 上编译出来的程序走 epoll 和 splice。在 macOS 上编译出来的程序功能相同，数据面是用户态拷贝。Windows 包只包含客户端。

./deploy.sh 会更新服务器上的程序，以及管理页提供的 punch-macos、punch-linux、punch-windows.exe。配置文件、证书和 punch-clients.json 留在服务器上，不会被这次同步盖掉。

加一个管理接口

路由表在 src/admin.rs 的 routes()。加两处：

  1. 写 async fn my_api(app: Arc<App>, req: Request) -> Response。
  2. 在 routes() 里加一行，例如 Route::get("/api/my-api", my_api)。也有 Route::post、Route::put 和 Route::delete。

路径写成 /api/... 就会自动检查 api key。路径里的 :id 用 req.param("id") 取，目前一段路径只支持一个这种参数。返回用 Response::json 或 Response::err。
